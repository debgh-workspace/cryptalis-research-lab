# Complete fresh native CF1 read: correctness-only public fixture prototype

This is an isolated research implementation. No timing, product integration, dependency change, provider access, database operation, or Git change is selected. S20 source remains unchanged. Python retains exact context/frame admission, NULL, pre/post resolution, strict UTF-8 and NUL handling. Native work fuses full root-salt/HKDF, AAD composition, AES-256-GCM-SIV decrypt, search derivation and full HMAC comparison, with fresh per-call state.

The fixed ABI has nine positional arguments: frame; representation integer 0/1; domain16; tenant16; field16; digest32; typed record bytes; payload material tuple; search material tuple or None. A material tuple is (root32, material domain16, material tenant16, root ID16, generation4). Material salt context is not inferred from active policy. The typed record is UUID16 or the exact nested 25-byte int64 tuple. All tuples/bytes are exact immutable built-ins. The helper holds the GIL.

The default OpenSSL provider is selected with `provider=default` for each cipher/digest/KDF/MAC and nested digest. This is not private provider isolation. Existing GCC/system OpenSSL 3.5.7 are used. The oracle uses the existing pinned virtual environment at repo/.venv/bin/python, without resolving that executable path, cryptography 50.0.2 and bundled OpenSSL 4.0.3. This difference prohibits pure wrapper/context/backend attribution and product backend admission.

Private failure categories deliberately preserve observable stage mapping: setup/derive/AAD/result-allocation/MAC failure maps to CryptoBackendUnavailable; returned data/update or final failure maps to AuthenticationFailed; successful AEAD with term disagreement maps to RepresentationMismatch. The data-processing label is NOT proof of an authentication cause: operational provider failures can produce that result. No error string/queue content is used to classify causes. The helper omits pyca's unused encryption-base creation and context-copy/fallback calls. Full allocation/fault equivalence is not claimed. Result reservation precedes authentication but does not recreate pyca's allocation order or every allocator call. Arbitrary Python allocation exceptions outside primitive regions are not newly normalized.

Native cleanup clears scratch plaintext, derived keys and owned temporary secret arrays; it cannot prove erasure of immutable Python roots/results, OpenSSL internals, allocator copies or registers. On a nonempty OpenSSL error queue it sets a mark and pops new errors to that mark; on an initially empty queue it clears only the operation's queue. Queue-capacity overflow, concurrent replacement and arbitrary provider corruption remain outside the guarantee. Cleanup of resources uses the appropriate null-safe EVP free functions.

The diagnostic build alone includes an explicit per-call finite site selector. The normal helper has no test hook. A compile-only skip-term mutant and separately named Python skip-final-resolution mutant are permitted only as correctness negative controls. No candidate control changes product modules. Failure injections simulate returned stage failure, not real allocator exhaustion/provider shutdown or complete fault equivalence.

The full design matrix and its broader diagnostic/primitive coverage remain a separate completeness gate. Each receipt states exact executed case IDs, pins, Python optimization flags, and any missing cases. No timing may start until root independent source and evidence review approves it. Missing sanitizer/leak or lifecycle evidence is UNKNOWN, not PASS. No production/readiness/performance claim follows.
