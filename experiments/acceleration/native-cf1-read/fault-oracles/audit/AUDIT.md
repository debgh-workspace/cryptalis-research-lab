## Actual mapper and safe fields

The new harness does not replace _native_encoded or duplicate its translation. It saves the research wrapper's native_cf1 module reference, temporarily routes open_encoded calls to the existing binary's open_fault or open_encoded, and calls unchanged open_text_native. The router has no catch/mapping logic. The original module is restored in finally and mapper function identity is checked. Thus recorded RuntimeError categories traverse the unchanged mapper and full wrapper; successful calls continue through strict decoding and final resolutions. No product function/module is replaced.

Refusals compare exception class name, code, stage, retryable, effects, remedy, a nonempty string operation ID, suppressed explicit cause, resolution trace and helper-call count. Source additionally requires args to equal the canonical safe message template containing that invocation's own operation ID. Literal IDs and messages are deliberately not stored/comparable across invocations. `__cause__ is None` and `__suppress_context__` are checked; internal `__context__` and arbitrary extra exception attributes are not asserted absent. This is the stated safe diagnostic schema, not proof that every possible exception property or traceback contains no data. Native categories themselves are fixed strings in the inspected C source.

## Remaining limits

Recovery establishes subsequent output, not cleanup/resource balance, leak freedom, memory erasure, error-queue preservation, cancellation safety or concurrent isolation. No new sanitizer/resource accounting or actual provider-identity attestation is supplied.
