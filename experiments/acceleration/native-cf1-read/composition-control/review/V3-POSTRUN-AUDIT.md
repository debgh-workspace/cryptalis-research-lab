# Independent S v3 postrun data audit

2026-10-14. Verdict: PASS for the bounded receipt/data-consistency scope below. This audit did not import candidate or harness modules, build anything, rerun tests or execute cryptographic operations. It used independently written stdlib-only JSON/hash inspection, recorded in audit_v3_data.py and V3-DATA-AUDIT.json. Supplemental corpus-order inspection is recorded in V3-CORPUS-ORDER-AUDIT.json. Writes stayed in this review directory.

## Findings

All 13,162 explicit checks in the main audit passed, plus independent primitive-order checks for all 2,196 O0/O1 corpus records. No discrepancy requiring correction was found.

- Both normal and observed compiler receipts report successful exit, exact frozen compiler command/flags/source, direct-child reaping and no cleanup error. Source, binary and build receipt hashes match. Their governing manifest is the independently reviewed PREBUILD_v3 digest 1b7facb755f993473f9ec033d0699dff949125f1f377e66d437899eb2b4b92ad.
- All 1,635 pinned input files were independently rehashed and matched. All seven cache inventories match, including existing cryptography/stdlib bytecode, and tool/Python resolved origins match. Original ARTIFACTS, v2 and v3 artifact manifests match their current files. All 124 entries in RUN_ARTIFACTS_v3 match actual bytes.
- Eight positive runs contain the full ordered expected results: 134 normal-direct, 723 observed-direct, 522 full-wrapper and 1,098 corpus records, separately under optimization 0 and 1. This is 4,954 complete positive observation records, not merely successful status/count fields.
- Direct/wrapper records were compared recursively with exact JSON types and full dictionary fields against frozen expectations. Full returned bytes/text, exception metadata, resolution arguments and order, primitive order, acquisition/release/reserve/decref/transfer counters, queue codes and expiry hook counts match.
- Resource expectations were also independently reconstructed from the reviewed API lifecycle rather than trusting the manifest count fields alone. Expected queue values were recomputed from ERR_PACK(USER=128,reason101/102). This checks the finite selector/counter contract; it does not establish provider-internal memory behavior.
- Six search-only expiry records per optimization mode require final payload resolution followed by final search refusal, exact KeyUnavailable fields, one hook and no output. Payload-only expiry, repeated success and fault lifecycle records also match. Static source review establishes that the valid/fault/recovery records use the same grouped PreparedKeys instance; serialized receipts alone cannot establish object identity.
- Every corpus record's actual result was matched to its untouched frozen corpus expectation, including complete strings/types and resolution traces. Decode hooks and nonce-observer counts match their declared cases. A supplementary independent derivation from frozen descriptor, crypto-boundary admission and authentication-failure precedence confirms all 0/3/6 primitive call sequences, rather than accepting the legacy Boolean native_calls marker as a primitive count.
- All 30 negative runs have the intended RuntimeError comparator rejection and nonzero child exit, with accepted-negative receipts. The audit checks the exact designated target, original actual record against its frozen expectation, and the exact expected transformation into the mutated record. Unexpected error types, a mutated expectation, a no-op mutation or a mismatching original would fail this audit. Direct/wrapper preceding observation prefixes also match their full frozen ordered prefixes.
- Every child and parent post-pin/cache receipt reports PASS; receipt hashes bind acceptance files to child output and supervisor records. Runtime origins, mapped libcrypto path and build bindings agree. The full matrix has no duplicate suite/kind/mode/optimization tuple and contains exactly eight positives and thirty expected negatives.
- All launch supervisor records report no termination reason, direct-child reap, empty cleanup_errors and the frozen 180-second/2-MiB-per-stream limits. Compiler records use the frozen 60-second limit. All explicitly report descendants_verified_absent=false. The audit does not reinterpret a termination attempt as evidence every descendant disappeared.

## Bounded conclusion and limitations

The frozen S control has internally consistent evidence for this finite normal/observed direct ABI, wrapper, corpus and actual-observation-negative matrix in both optimization modes. The observed source corresponds to the reviewed isolated counter instrumentation; none of these observations transfer automatically to a different binary, platform, backend or product integration.

These are file/receipt consistency findings, not cryptographically attested proof of all recorded machine actions. No fresh cryptographic recomputation of every frozen expected output was performed; expected values remain the independently sourced, previously reviewed public fixture constants. Current rehashes plus recorded pre/post checks establish the available provenance evidence, not protection against arbitrary historical manipulation.

Successful and intended-negative processes do not stress every supervisor crash, timeout, interruption or I/O-failure cleanup path. Actual inherited-key fork qualification and absence of escaping descendants remain open. Native ownership counters count API/reference events, not allocator-internal frees, leak freedom or erasure. Ordinary unmarked queues 0/1/2 are qualified only within these observations; marked/overflow queues, mark/pop failure, returned-length/property branches, partially failing EVP calls, real allocator failures and broader/nested-provider correspondence remain unqualified.

No timing was audited or admitted. Original five-arm mechanism controls, failure-policy disposition, full DESIGN completion, database/end-to-end qualification and product adoption remain separate gates. A finite S admission result does not settle backend attribution or explain F-versus-P speed.
