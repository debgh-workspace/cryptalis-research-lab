- Set B = 16,777,728. Starting total is 4. Each exact bytes length is nonnegative; short-circuit `n > B-4 || total > B-4-n` avoids subtracting an unbounded n. Accepted iterations maintain total <= B, so subsequent additions and 32-bit count/length casts are safe on supported CPython platforms. Single-part maximum length is B-8 = 16,777,720. The 16-MiB equality message occupies 16,777,236 bytes, below B. This is bounded internal framing, not arbitrary-size public serialization.
- All input/type/bounds validation precedes result allocation. One owned PyBytes result is allocated; NULL propagates allocation error. After allocation, only bounded stores/copies run and the owned reference transfers to Python. Borrowed inputs survive under the GIL/argument tuple; there are no INCREF/DECREF branches to balance. The module owns no custom resources. Static reasoning does not establish empirical refcount or allocator behavior.
- `tuple_alloc_failure` validates first then raises MemoryError before the real allocation. It proves a diagnostic refusal path only; it does not force PyBytes allocation failure or module-init failure. The normal build excludes the diagnostic entry. Immutable Python plaintext/result copies are not securely erased, and none is claimed.
