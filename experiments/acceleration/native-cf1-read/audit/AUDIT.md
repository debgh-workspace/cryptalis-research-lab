## Manifest-before-candidate mechanism and limitations

Generator imports unchanged S20 and pyca, never the candidate, constructs fixtures, freezes outcomes and writes cases.json exclusively. build.py hashes cases, fixture bytes and harness/source before compilation and records binary/dependency hashes after compilation. launch.py verifies listed hashes before native import, verifies oracle versions/origin, then imports native and validates its origin/backend before calling validation. These are useful input-provenance checks, not signed chronology or independent proof that the recorded execution happened.

Only the 1,035 public cases are enumerated with expected outcomes in cases.json. The 147 normal supplements and 64 diagnostic supplements are generated by pinned Python source; their planned IDs are assembled AFTER execution, and expected outcomes often are literals or reused base expectations. Thus the end-of-run ID equality check rejects omission/duplication/reordering relative to that source, but does not implement DESIGN's complete pre-run JSON enumeration. The build is allowed to proceed without cases.json because it uses glob; validate later fails when absent. Generator freezes only after running the oracle, and freeze-01.json does not itself record the output manifest digest. The later build pin supplies the digest link, not an authenticated temporal record.

## Exact correctness coverage gaps and misleading interpretations

### A. Frozen independent data
1. Missing all six additional primitive oracle entries: four AES-256-GCM-SIV vectors, RFC5869 HKDF (42 bytes), RFC4231 HMAC.
2. Missing diagnostic comparison of frozen payload/search salts and keys, AAD and header intermediates. Diagnostic API exposes faults, not intermediate values. The eight public expected texts are hashed by observe; it does not explicitly compare to frozen text/encoded_text in validation. For the grid, generation first checks product round-trip exact equality; validation then compares length/SHA-256, not exact returned text.
3. Frozen byte preservation is verified, but unchanged sealing/equality-term parity for the frozen eight is not exercised by this harness. Query-term parity covers the 32 equality grid fixtures only; sealing supplies the 64 grid inputs.

### B. Valid grid and boundaries
4. The required 64 grid combinations, eight NULL, six int64 endpoint, two combined nil record/tenant, two maximum and two over-bound cases exist. Exact eight UTF-8 payloads are in generator source, but grid fixture records and cases.json do not freeze their exact UTF-8 bytes/text, only baseline output length/hash. Ciphertexts are newly randomized by unchanged seal_text, so rerunning generation is not byte-deterministic; case identities and selected values are deterministic. Do not call the resulting fixture bytes reproducibly generated.

### C. Context and frame coverage
5. Missing table-derived descriptor relocation for each of eight codec/representation modes. Wrong field/digest/record/domain and tenant cases exist; domain cases rebuild matching policy/material and therefore test cryptographic relocation, not domain policy mismatch. Missing explicit mismatched policy-domain cases (including domain-policy-plus-malformed-frame precedence variant if claimed).
6. Tenant-column wrong-tenant cases do rebuild matching alternate policy/material, so required cryptographic relocation IS covered. Single-tenant mismatch and immediate policy-tenant rejection are covered. Do not incorrectly list tenant relocation as absent.
7. Unadmitted payload cases exist on all frozen vectors; search on four equality grid modes; readable older payload/search generations are covered jointly through active_new. No gap is asserted merely because older payload/search are exercised together.
8. All named frozen frame operations, explicit shape-valid representation disagreement, public class refusals and record-type refusals are present.

### D. Authenticated content and precedence
9. Valid-AEAD invalid UTF-8/NUL for both representations, consistent/inconsistent equality terms, all eight specified precedence categories and valid-AEAD wrong-term are represented. Missing full diagnostic fault-result comparisons are described below rather than misreporting these base pairs as absent.

### E. Per-use state and fresh release
10. The interleave/0..2 sequence is grid-000-1, grid-100-1, grid-000-1. Both fixtures use the SAME tenant UUID(4), record UUID(5), domain, field and roots. It changes representation, not tenants/records. Required true A/B/A tenant-and-record isolation is absent. Thread/event-loop fixtures share those same contexts too, weakening the requested cross-scope isolation demonstration.
11. Fresh invocation per case reconstructs PreparedKeys. Valid/invalid/valid exercises the same frame under wrong/correct payload roots in separate invocations, but does not exercise an already-used PreparedKeys object transitioning from valid to expired/current-state-invalid and then a fresh valid call. No invocation-count instrumentation proves every non-NULL repeatedly enters native work or that NULL never does.
12. Initial/final payload expiry, equality search-only initial/final expiry, actual inherited-key fork rejection and fresh child success are present. After-native expiry is present for storage/equality but compared only by exception class. Expiry at final _resolve is a final-resolution injection; no distinct injection during decode-to-final-check boundary exists. No post-native or post-decode PID-change case exists (actual fork tests pre-use PID rejection).
13. Resolution trace is complete for the base manifest successes/failures; after-native checks and fault injections compare exception class only, and fork/inherited compares only the class. They do not verify exact arguments/traces, diagnostic fields or operation ID against a frozen expected record for those supplemental failures.

### F. Native ABI and fault completeness
14. 100 ABI cases include exact-byte type/length failures, nested material lengths/types, arity, missing/extra bundles, typed-record malformed length/prefix, representation values, empty/over frame and storage extra search. Maximum valid frames pass through the helper via public max cases. No separate direct-ABI maximum case is needed to pretend this boundary is wholly untested.
15. Named 31 failure sites cover the implemented digest/KDF/cipher/MAC/result/scratch boundaries and recovery. No measured allocation/context create/free balance exists; successful recovery is not leak evidence. Internal EVP allocations, real partially failing providers and actual allocator exhaustion are not simulated. Error queue ERR_set_mark failure and cipher key/IV-property failure paths are not fault-injected; source-derived complete failure-branch enumeration is therefore broader than the current site list. Term-comparison rejection is covered by valid-aead-wrong-term, not an allocation site.
16. Fault assertions check only exception class, using an adapter that duplicates native_read._native_encoded's mapping rather than exercising that mapper for injected errors. They omit frozen diagnostic code/stage/retryable/effects/remedy/operation-presence/trace equality. The adapters can diverge without these tests detecting it.
17. Wrong-output control is equal('negative-output','wrong','expected') BEFORE candidate work. It proves the equality helper raises under O0/O1, but does not alter candidate decoded output and therefore does not prove that the end-to-end oracle catches a wrong decoded candidate value. Skip-term and skip-final controls do exercise candidate/mutant semantics meaningfully.

## Provenance and claim boundaries

- Runtime receipts record native version, binary origin and source origin, but do not record actual provider identity or cipher properties/availability as a separate result. Source fetch properties and successful executions establish a narrower fact. S20 keys origin is not separately enforced like cf1, though its intended bytes are pinned.
- SCOPE says each receipt records any missing cases; receipt schema has no missing-cases inventory. Only this report/existing caveats explain incompleteness. PASS means exact implemented list passed, not complete DESIGN.
- Preserve the explicit known caveat: setup/derive/AAD/result-allocation/MAC map to backend; data/update/final map to authentication by observable stage. Generic failure at data/final is not causal proof of authentication failure and can hide operational failures. Do not upgrade this to full backend-error semantic equivalence.
- Preserve omitted pyca calls/allocation-order caveat: unused encryption base, context copy/fallback and allocator schedule are not reproduced. Nothing here repairs that limit or grants product/backend admission.
- No certain product-output defect was established by this static data audit. The certain harness defects are overstated isolation labels, tautological wrong-output control, class-only supplemental failure checks, and incomplete pre-frozen enumeration. Existing positive evidence remains useful when described narrowly.
