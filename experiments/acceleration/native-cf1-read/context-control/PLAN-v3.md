# Additive v3 containment and cache provenance

All v1/v2 files and reviewed native C/wrapper are preserved. This is a source-only addition, NOT execution approval. v3 keeps the same374 D /314 paired F diagnostic observations and five negative modes per arm/mode; it does not add correctness coverage or change source policy.

The concrete `launch_v3.py` supervisor takes six positional arguments: kind(build/run), arm(D/F), local build name, mode(normal/diagnostic for build; positive/output/copy/free/stage/trace for run), optimization(0/1), unique local label. Build requires optimization0. It exclusively creates private cache roots, receipts and capped output files; names allow only letters/digits/hyphen/underscore. Every child is a new process-group leader with stdin closed. One120-second monotonic deadline applies to the entire child group. Each stdout/stderr stream is capped at1MiB; crossing a cap kills the group. The supervisor kills remaining group members on child failure, deadline, stream overflow, and completion, then reaps its direct child. Cleanup wait is bounded at5 seconds per wait attempt. It cannot waitpid non-child grandchildren; process-group kill, direct-child reaping and that limit are stated separately. No timeout/overflow is an accepted negative.

Bytecode strategy: every child uses the pinned venv executable with -E -S -B and -X pycache_prefix pointing to the exclusively created empty per-launch directory. -E ignores Python environment configuration, -S disables site initialization/.pth/user-site/sitecustomize execution, and -B prohibits new bytecode writes. The selected venv site-packages path is explicitly added only by the diagnostic runner after freeze verification. This intentionally changes startup mechanics, not interpreter executable identity, algorithm or provider. Existing shared caches are neither read through source-loader cache lookup nor deleted. A PathFinder replacement rejects sourceless .pyc specs before project imports. Built-in/frozen modules and pinned extension libraries remain permitted. This does not claim isolation against arbitrary new custom importers or malicious mutation outside the frozen research process.

The cache prefix and all startup flags are checked before importing any project/native module. Its exact empty inventory is checked before and after, including error exits. Existing startup/import/linker environment overrides are rejected rather than silently accepted. The cache guard itself and all source dependencies are pinned by the supervisor before launch. Runtime stdlib sources/extensions and permitted cffi files are pinned alongside original cryptography/S20/toolchain inputs; no candidate module is imported to obtain pins.

`run_v3.py` and `build_v3.py` retain their v2 logic but read FREEZE-v3/build-v3 and enforce fresh-prefix startup. Final source/dependency/cache checks run in finally on positive, negative and error exits. Original intended mismatch remains in its own error fields; an independent integrity_errors list and FAIL_INTEGRITY status prevent a provenance failure from being accepted as a successful negative. The supervisor also repeats frozen source checks on every exit and demands the precise mismatch message, exit1, verified unmodified record, and actual differing mutated record for negative acceptance. Root/independent review still audits exact changed field from receipts; nonzero alone never suffices.

No build/run is chained automatically beyond the explicitly selected single child. All outcomes are exclusive artifacts. No provider settings, installation, shared-cache cleanup, database, network or Git actions are added. The root must approve the bounded concrete scope after review; full normal-wrapper/ABI-fork/expiry/removal-mutant admission remains open.
