# Fixture ownership/preflight hardening V1

Source-only proposal, no syntax check/import/collection/tests/DB execution. INPUTS.json was written before candidate creation. Original combined222 source and all earlier evidence are preserved. This changes test infrastructure only; no product or authority contract changes.

Move the existing runtime PostgreSQL16/nonprivileged-role checks ahead of engine creation and all fixture mutations. Use explicit exceptions rather than optimizable assertions. Existing genuine credential/preflight wrapper, role separation, exact cluster and exclusive ownership admission remain required; this helper does not supply those proofs.

A small context manager creates the generated schema and enters its cleanup-protected body only after the CREATE transaction context returns successfully. A create/collision failure or ambiguous commit therefore never issues a guessed DROP. Such ambiguity may leave a restricted fixture for separately authorized inspection. The owned context cleans up before final owner disposal, including when fixture setup/body/runtime disposal fails. Existing schema-local ACL statements and test oracles are unchanged. Runtime disposal remains before schema removal after a successfully acquired fixture.

Recording tests declare nine cases: three preflight refusals before engine access; one successful ordering checkpoint; two unacquired create/commit failures; three owned normal/error/interruption cleanups. They call actual candidate helpers with recording connections and no database. Test module import must be bound to the isolated candidate, not the frozen source. No run is selected here. No fabricated pytest preflight or production-role authorization is proposed. The original48 native assertions remain unchanged and unexecuted.

Limits: successfully committed CREATE is local acquisition evidence under existing exclusive-lab ownership, not proof against an external actor replacing the schema before cleanup. DROP CASCADE can follow dependencies and needs existing containment admission. Cleanup failure may replace a body error as in prior fixture behavior; this patch does not claim a comprehensive cleanup-exception redesign. No new credentials/roles/global/default privileges, session termination or runtime grant is added. Full native file statically requires84 fixture lifecycles across both profiles, correcting the old68 claim. Source acceptance and separate no-DB runner admission are prerequisites to any recording test; native operation authority remains undecided.
