## Independent expectations

The simple fixture uses schema={}, guard=["A"], scope count N=1, one canonical
table UUID and a 64-zero membership digest. It is a sizing fixture, not a native
schema or admitted guard. With a UUID cursor, the maximum compact wire has 391
bytes; it has 21 punctuation separators, giving a 412-byte native-spacing
prediction. The independent ABORTED shape has 388 compact / 409 predicted native
bytes. The full expected canonical wire is written as byte literals in the test,
not generated by the reference or its constructor.

Hand-derived maxima for that fixture:

| Direction / record codec | Compact bytes | Separators | Candidate native bytes | ABORTED compact / candidate native |
|---|---:|---:|---:|---:|
| Forward UUID | 391 | 21 | 412 | 388 / 409 |
| Forward int64 | 375 | 21 | 396 | 372 / 393 |
| Reverse UUID | 438 | 24 | 462 | 435 / 459 |
| Reverse int64 | 422 | 24 | 446 | 419 / 443 |

For N=0, both codecs reserve NULL: forward 357 compact + 21 separators = 378
candidate native; reverse 404 + 24 = 428. The independent two-model UUID
forward maximum is 732 compact + 39 separators = 771 candidate native. These
are source/math predictions, not PostgreSQL observations.

Derivation for one UUID model: six-member progress punctuation/keys contributes
57 bytes; scope contributes 91 bytes (N=1); cursor 38; rows/chunks one each;
schema 2; guard 5. This totals 195. A one-entry UUID-keyed models map contributes
41 more, totaling 236. Phase/root framing contributes 32, and the full forward
verification member contributes 123: 391. A second model adds 235 model-map
bytes and 106 verification-map bytes: 732. A signed-int64 cursor removes 16
bytes. Reverse framing replaces forward root/verification framing with 202
bytes: 438 or 422. The empty-state NULL cursor removes 34 or 18 bytes. An abort
replaces a ten-character phase by seven characters, removing three bytes.
