# Cryptalis Research Preview

Cryptalis adds application-side authenticated protection to admitted text fields in a Python/SQLAlchemy/PostgreSQL backend. A JSON declaration selects storage and exact equality/IN/tenant-scoped uniqueness. Current Python APIs support read-only planning, maintenance protection, bounded native ORM operations, current-data decrypt-back and removal within admitted schema profiles.

**Internal evaluation with disposable synthetic data only. All seven production gates remain UNKNOWN.** Unsupported paths fail explicitly. The [capability/refusal matrix](https://github.com/debgh-workspace/cryptalis-research-lab/blob/d952c505a4666266019e32f27c77f93edd5151ca/preview/docs/source221-v4/CAPABILITIES.md) and [security/delivery limits](https://github.com/debgh-workspace/cryptalis-research-lab/blob/d952c505a4666266019e32f27c77f93edd5151ca/preview/docs/source221-v4/KNOWN-LIMITATIONS.md) define the boundary. ## Start here

Read the [manifest requirements](https://github.com/debgh-workspace/cryptalis-research-lab/blob/d952c505a4666266019e32f27c77f93edd5151ca/preview/docs/source221-v4/MANIFEST.md) and [host prerequisites](https://github.com/debgh-workspace/cryptalis-research-lab/blob/d952c505a4666266019e32f27c77f93edd5151ca/preview/docs/source221-v4/HOST-INPUTS.md), then the [small public-API quickstart](https://github.com/debgh-workspace/cryptalis-research-lab/blob/d952c505a4666266019e32f27c77f93edd5151ca/preview/docs/source221-v4/QUICKSTART.md). The actual attachment is `cryptalis.sqlalchemy.attach(mapping, engine, lock=lock_bytes, keys=keyrings, deployment=(plan, active_pin))`; await it for an AsyncEngine. Attachment does not migrate data, authenticate users or replace authorization. Runtime roles must be restricted, writers inventoried, keys explicitly supplied and current deployment authority kept outside database restore.

New protection plans inventory remembered index designation by default. Older artifacts without metadata are not silently upgraded. [Recovery and removal](https://github.com/debgh-workspace/cryptalis-research-lab/blob/d952c505a4666266019e32f27c77f93edd5151ca/preview/docs/source221-v4/RECOVERY.md) state the safe survivor/abort paths and blocked post-loss cases. Physical heap ordering and arbitrary metadata preservation are not promised.
